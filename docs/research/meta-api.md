# Meta Model API integration research

**Reviewed 2026-10-30.** Scope: public first-party Meta documentation and legal pages, not a live API or account test. Facts below describe the sources on that date; pricing, availability, policies and documentation can change. This is technical research, not legal approval. The review used the project `AGENTS.md` rules and separated page-confirmed statements from design inferences.

## Decision and launch blockers

**Do not enable public signup or BYOK inference yet.** Meta's [Terms §3.1 and §10.1](https://dev.meta.ai/legal/terms-of-service) prohibit sharing or transferring API keys to third parties without prior written permission and restrict accessing services on another party's behalf, with an exception for end users interfacing through an integrated product. Meta's [key-sharing FAQ](https://dev.meta.ai/help/api-keys/sharing-api-keys) says keys must not be shared outside the issuing team, including contractors or partners. **Cautious inference for Chron’s planned BYOK/server flow:** an individual's submission of their key to an independently operated Chron server may constitute prohibited third-party sharing; the integrated-product exception does not clearly resolve that specific BYOK flow. Obtain written Meta clarification or permission for the exact flow before accepting keys; don't presume encryption cures the contractual issue.

Meta's terms §10.1 require both service users and integrated-product end users to be **18 or older**, and prohibit integrated products targeted at under-18s. Student users 18+ are a possible audience subject to other restrictions; a product aimed at minors conflicts with the published terms. [Terms](https://dev.meta.ai/legal/terms-of-service); [age FAQ](https://dev.meta.ai/help/accounts-and-login/age-requirement). Confirm audience, enforce eligibility and obtain qualified review before launch.

Chron’s current guidance prohibits “Powered by Meta AI” and Meta marks until written authorization; terms §7 say neither party receives trademark licenses or may use the other's names or marks in connection with the services. **Inference:** get written guidance/authorization on this exact attribution and independent-product disclosure before publishing it; do not assume the project wording grants rights. [Terms](https://dev.meta.ai/legal/terms-of-service).

## Verified service and interface

- Meta announced general global availability in September 2026, but actual access is conditional on supported territories, billing, age and account eligibility. Meta's [geographic policy](https://dev.meta.ai/legal/geographic-use-policy) is authoritative; [help](https://dev.meta.ai/help/accounts-and-login/supported-countries) says availability is in most territories where Meta AI and billing are supported. Check the live policy for both operator and end user locations; the terms prohibit making services and integrated products available in excluded areas. Do not interpret “global” as every jurisdiction. [Announcement](https://developers.meta.com/blog/meta-connect-recap/); [Terms §10.1](https://dev.meta.ai/legal/terms-of-service).
- The first-party base is `https://api.meta.ai/v1`, using `Authorization: Bearer <key>`. Documented generation endpoints are `POST /v1/responses`, `/v1/chat/completions`, and `/v1/messages`; `GET /v1/models` lists available models. Responses supports reasoning replay and agent loops; Chat Completions does not carry reasoning between turns. [API reference](https://dev.meta.ai/docs/api-reference); [protocol comparison](https://dev.meta.ai/docs/protocols). The project's inference restriction excludes third-party hosted alternatives, even when they serve Meta models.
- Current documented standard text IDs include `muse-wonder-1.0` (preview), `muse-spark-1.3`, `muse-spark-1.2`, and `muse-spark-1.1`; Wonder and Spark list a 1,048,576-token context. Other hosted models include `muse-image-1.0`, `muse-voice-transcribe-1.0`, and `sam-3.1`. Spark 1.2 and 1.3 also have `-contributor` variants. Meta says Llama, Muse Spark Open and Muse Glimmer are separate self-hosted or externally hosted offerings, not models run through Model API. Check actual account and endpoint availability with `GET /v1/models` before selecting a model; do not hardcode preview availability as a guarantee. [Overview](https://dev.meta.ai/docs/overview); [Llama FAQ](https://dev.meta.ai/help/about-model-api/llama-and-model-api).
- Keys are team-scoped. Meta recommends a secrets manager, no client-side hardcoding or source-control commits. Deletion immediately stops calls and requires at least two keys in the team before deleting one; do not promise Chron can revoke a key on Meta's behalf. [Create key](https://dev.meta.ai/help/api-keys/create-api-key); [delete key](https://dev.meta.ai/help/api-keys/delete-api-key). **Design inference, conditional on permission:** encrypt stored keys with authenticated encryption and keys outside the database, use them only on the server, redact secrets from logs, URLs, errors and responses, and allow local removal/replacement.

## Capabilities and constraints

- **Tools and structured results:** The model can request developer-defined function calls; application code must actually run tools and handle their results. Meta documents parallel calls and streamed arguments. JSON Schema output uses `text.format` on Responses and `response_format` on Chat Completions. Schema validation rejects recursive references, nesting over 10 levels, and more than 5,000 properties; additional constraints apply. Schema shape does not establish factual correctness or authorization. Validate arguments and outputs on the server; enforce explicit tool permissions, timeouts, output limits and approval for consequential actions. [Tool calling](https://dev.meta.ai/docs/tool-calling); [structured output](https://dev.meta.ai/docs/structured-output).
- **Streaming:** Responses `stream: true` yields typed server-sent events, including text deltas and tool argument deltas. Handle completion, incomplete, `response.failed`, and stream-level `error` events; an error after streaming starts need not be an HTTP error. Non-streaming long requests may time out. [Responses](https://dev.meta.ai/docs/protocols/responses); [error handling](https://dev.meta.ai/docs/error-handling).
- **Search:** `web_search` on Responses and Messages can yield citations; the model decides whether to search, so its presence does not guarantee a search or citations. Chat Completions does not support search grounding. Inspect the returned search calls and citation annotations, expose uncertainty, and verify sources; Meta notes incomplete coverage. Search costs $2.50 per 1,000 queries in addition to token costs. [Search grounding](https://dev.meta.ai/docs/search-grounding); [pricing](https://dev.meta.ai/docs/pricing-rate-limits).
- **Files:** `POST /v1/files` uploads, with list/get/delete endpoints. Uploads default to no expiration; optional expiry ranges from one hour to 30 days. The documented limit is 1 GiB per upload and 100 GiB per team; inline files max 50 MB. PDF extraction reads text from the first 100 pages and images from the first 50. Track ownership and deletion, minimize material sent, and communicate incomplete coverage; confirm provider deletion and backup semantics rather than promising them. [File handling](https://dev.meta.ai/docs/file-handling).
- **Limits:** Meta publishes per-team, per-model RPM and TPM limits, not per-key limits. For example, Wonder 1.0 and Spark 1.3 list 3,000 RPM and 4 million TPM; actual team limits are in the account dashboard. Handle 429 with bounded exponential backoff, jitter and any `Retry-After`; enforce independent application budgets. [Pricing and limits](https://dev.meta.ai/docs/pricing-rate-limits); [limits FAQ](https://dev.meta.ai/help/usage-and-limits/rate-limits).

## Data, billing and policy

- Under Standard Services, Meta states it does not use request content to train Meta models, but retains and processes content and usage data as needed for service delivery, law, safety, security and policy review. Terms incorporate processor and security terms. This is **not** a zero-retention promise; standard retention periods were not established by the reviewed terms. [Terms §§4–5](https://dev.meta.ai/legal/terms-of-service).
- Contributor variants permit Meta to train and improve models with content and prohibit submitting sensitive, confidential or personal information. Student notes and documents may contain such material; **inference:** disable Contributor IDs for Chron rather than assume inputs are safe. Meta notes standard content becomes Contributor content if included in a Contributor request. [Terms §6](https://dev.meta.ai/legal/terms-of-service); [Contributor FAQ](https://dev.meta.ai/help/policies-and-privacy/contributor-tier).
- ZDR is separately enabled by Meta for qualified organizations/teams, not a default or self-service setting. It applies only to keys of enabled organizations/teams on direct Meta calls, may vary by model, and excludes personal keys and other teams. Stateful server references, background requests, file uploads, web search and Contributor mode are unavailable. Flagged policy-violation inputs and outputs may be retained up to two years; account, usage and operational metadata and support submissions also remain. Third-party tool processing is outside ZDR. **Inference:** BYOK cannot promise ZDR generally, and enabling it changes the research/files design. [ZDR FAQ](https://dev.meta.ai/help/policies-and-privacy/zero-data-retention).
- Pricing is usage based, varies by model and changes. The cited schedule lists Wonder Standard at $4 per million input tokens, $20 per million output tokens, and $0.20 per million cached input tokens. Billing requires a payment method and legal name/address; charges occur at a payment threshold or monthly. Meta's spend alert is not a hard cap. Show actual provider charges and communicate that the key owner's team is billed; do not invent Chron fees or caps. [Pricing](https://dev.meta.ai/docs/pricing-rate-limits); [billing setup](https://dev.meta.ai/help/billing/set-up-billing); [billing](https://dev.meta.ai/help/billing/api-bill); [spend alerts](https://dev.meta.ai/help/billing/spend-limit-alert).
- Meta's terms describe ownership of inputs and outputs subject to their terms and require integrated-product operators to ensure end-user compliance, accurate privacy disclosures and applicable AI labeling. Outputs may contain third-party licensed material; do not treat ownership language as a guarantee of copyrightability or non-infringement. [Terms §§1, 4–6](https://dev.meta.ai/legal/terms-of-service); [output FAQ](https://dev.meta.ai/help/policies-and-privacy/output-copyright).

## Policy and processor/security review (2026-10-30)

**Page-confirmed: Acceptable Use Policy.** The [Meta Model API AUP](https://dev.meta.ai/legal/acceptable-use-policy) applies to services, outputs, actions and integrated products. It prohibits collecting, processing, disclosing, generating or inferring private or sensitive information without the right to do so under applicable law; emotion recognition in education except as permitted by applicable law; and detrimental classification based on personal traits under its specified conditions. It prohibits representing outputs as human-generated, removing or failing to preserve Meta-applied provenance signals, and using outputs in decisions affecting a person’s fundamental rights, health or safety without review by a qualified person. It bars agent operations that evade oversight and consequential or irreversible actions through connected services without appropriate authorization, human oversight, review and confirmation. Meta may grant exceptions for educational or research purposes at its discretion; education alone is not an exception. The [Terms §§4.1, 10](https://dev.meta.ai/legal/terms-of-service) additionally require rights to submit inputs, prohibit specified uses of outputs to develop competing models absent authorization, and require prompt notice to Meta of known or suspected §10.1 breaches; evaluating one's own systems is expressly excepted from that particular competing-model restriction.

**Page-confirmed: processing and retention.** [Terms §§2, 4.4, 5.1, 14](https://dev.meta.ai/legal/terms-of-service) incorporate the Global Processor Terms and Data Security Terms. For Standard Services Meta describes its processor/service-provider role, the customer authorizes Meta to engage listed subprocessors, and Meta instructs customers seeking assistance with privacy-rights requests to contact Meta through their accounts with necessary information. Meta retains content and usage data as needed for the enumerated service, legal, safety, security and policy purposes; no general fixed retention or backup-deletion period is specified there. The [Data Commitments](https://dev.meta.ai/legal/commitments) say users can view and delete content through their accounts subject to retention under the terms. This does not establish a complete deletion deadline or prove that an independent Chron operator can perform deletion on behalf of a user's Meta account.

**Page-confirmed: security.** The [Data Commitments](https://dev.meta.ai/legal/commitments) state that content and customer data in transit use TLS 1.2 or later, storage is subject to strict access controls, and Meta maintains security testing, vulnerability management and incident response processes. Its stated ISMS protection describes *Customer Data*, which the page distinguishes from prompt and response *Content*; do not expand that wording into a claim that all content is encrypted at rest. Terms §14 says Meta treats Content and Customer Data in accordance with the Data Security Terms. The full linked [Meta Global Processor Terms](https://www.facebook.com/legal/terms/Meta-Global-Processor-Terms) and [Data Security Terms](https://www.facebook.com/legal/terms/data_security_terms) redirected to a blocked login page and could not be independently inspected. Their exact obligations, incident notification timelines, audit rights, transfers, deletion and subprocessor provisions remain **unverified**, including any terms that may supersede or qualify the public summaries.

**Chron launch implications — inference and project controls.** Keep inference and key collection disabled until the existing written BYOK clarification and adult eligibility gates are satisfied. Before enabling educational or research workflows, establish a lawful basis and necessary rights for submitted sources and personal data; define provenance preservation, AI disclosure, qualified review for covered decisions, and permissioned agent actions with human confirmation. Do not add educational emotion recognition unless the applicable-law exception is established and reviewed. Obtain and review the actual incorporated processor and security terms and any account-specific agreements; document provider retention, transfers, deletion, subprocessors, incidents and Chron’s own safeguards before final privacy notices or release. The reviewed AUP does not itself establish that all academic research is prohibited or that ordinary study assistance is a high-stakes decision.

## Official-source update (2026-11-02)

Meta's current first-party documentation confirms that the official Model API is available at `https://api.meta.ai/v1`. It documents Responses, Chat Completions, Messages, Files, Models, and Status interfaces. This confirms the product's required official inference mechanism exists; it does **not** establish permission for Chron's proposed per-user key flow. No account or API key was used, and no live API call was made. Check `GET /v1/models` with an authorized account before selecting a model; account availability, billing, quotas, and geography remain unverified. [API reference](https://dev.meta.ai/docs/api-reference); [overview](https://dev.meta.ai/docs/overview).

The official guides document function tools, streaming, search grounding, and structured outputs. The documented `strict` option defaults to `false` for function tools and structured output. Set it explicitly where supported, then validate inputs and outputs locally; strict schema handling does not replace authorization, factual verification, or tool permission checks. [Tool calling](https://dev.meta.ai/docs/tool-calling); [structured output](https://dev.meta.ai/docs/structured-output).

Two documentation inconsistencies need account-level confirmation before relying on these behaviors. The protocol comparison describes Messages `thinking` replay, while the Responses guide calls Responses the only endpoint that carries reasoning across calls. The file guide says uploaded files do not expire by default, while also describing optional expiration. Treat both as documentation conflicts; verify actual API behavior and deletion semantics rather than promising cross-turn reasoning or file expiry/deletion. [Protocol comparison](https://dev.meta.ai/docs/protocols); [Responses guide](https://dev.meta.ai/docs/protocols/responses); [file handling](https://dev.meta.ai/docs/file-handling).

The legal gate remains unchanged. Meta's Terms and key-sharing guidance restrict sharing team-scoped keys outside the issuing team. The integrated-product exception does not clearly authorize an independently operated Chron server to receive, store, and use each end user's key. Keep key intake and inference disabled until Meta provides written clarification or permission for that exact flow and qualified legal review is complete. The 18+ eligibility, geographic, and trademark/attribution gates also remain. [Terms](https://dev.meta.ai/legal/terms-of-service); [key-sharing FAQ](https://dev.meta.ai/help/api-keys/sharing-api-keys); [geographic policy](https://dev.meta.ai/legal/geographic-use-policy).
